# AI Tools Note

*(Summary below stays short and final-draft quality — write it last, once the log has real entries. The Development Log is the append-as-you-go record; do not prune it for length, only for accuracy.)*

## Tools used
- **Claude Code (Sonnet 5)** — primary dev partner for this build: design discussion, C# scripting, git/GitHub setup
- **Unity-MCP** (`com.ivanmurzak.unity.mcp`) — MCP server bridging Claude Code directly into the running Unity Editor for live GameObject/component/prefab/scene edits, not just file generation

## How used
Claude Code handled essentially all C# scripting (data models, the `GameStateUI` state machine, `ScoreCalculator`'s formula, click-to-assign/toggle/replay UI features) and the required submission docs (`MECHANIC_NOTE.md`, this log). Fable-advisor was reserved for genuinely architectural or scope-priority calls — early design-lock sanity passes, the asmdef/state-machine architecture, and a Day-3 remaining-time prioritization plan — not day-to-day implementation. Unity-MCP did live-Editor verification when connected (asset seeding, reading real component state to diagnose layout bugs, brute-force-validating the scoring formula against 1024 real assignments), and when it dropped mid-Day-3, work continued via direct asset-file edits and hand-recomputation rather than stalling, ending with a build-artifact audit that caught Unity-MCP's own runtime shipping inside the submitted player build.

## What stayed human-driven
- Mechanic choice (delegation task-assignment over communication-crisis / conflict-resolution alternatives)
- Every architecture call reviewed and iterated in real time, not accepted on first draft — e.g. rejected an initial `IGameState` state-machine split as unneeded ceremony and asked for an SRP-driven one instead, reversed an earlier "no asmdef" call mid-build, converted plain data classes to ScriptableObjects for Inspector tuning
- Scope cuts and scoring-formula tuning (burnout floor, urgency weights, tier cutoffs, the effort tweak that fixed the score ceiling)
- Every "needs a human" decision Fable flagged was decided by hand, not deferred to AI: GitHub repo visibility, PC vs. WebGL build target, whether to keep or trim the two scope-deviating features
- Final playtest judgment and bug triage — including catching two real AI mistakes in the moment (scaffold code written before being asked to start; an over-broad `git add` that staged the whole tree)
- Submission decision

This was a tightly-directed collaboration, not delegate-and-accept: direction came as short, specific corrections turn by turn (reject this pattern, use that one instead, split this file, fold Show/Hide into the same class) rather than open-ended prompts, and every non-trivial output — code, plan, or claim — was checked against the actual project state before being trusted.

## Honest reflection
AI sped up both the design phase and the mechanical/analytical grind: Fable review caught real design gaps early, live component-state reads solved three uGUI layout bugs that would otherwise have been trial-and-error, and the brute-force balance check caught a genuinely unreachable score tier (82.4% ceiling against an 85% cutoff) that hand-checking alone had only flagged as "close." Two catches right before submission stood out as the highest-value ones: independently re-verifying a self-reported bug fix against actual component state (it held) rather than trusting the report, and auditing the final build artifact, which caught Unity-MCP's own runtime and its ASP.NET Core/SignalR dependencies shipping inside the submitted Standalone player — a real thing that would have gone to the evaluator unnoticed. It also made two concrete mistakes needing a catch, not just catching human ones: writing scaffold code before being asked to start implementation, and once staging the entire working tree into a single commit from already-staged files. Both were caught immediately and reverted cleanly, which is itself the honest data point — human review stayed load-bearing the whole way through, not just at the design stage, and the tool-down stretch on Day 3 showed the same rigor (check real data, don't assume) held up without Unity-MCP available.
